## 1. Delivered Scope (`10.01`–`10.05` & `OWNER-20261105-05`)

1. **`10.01` — Manual External Payment Recording & S11 Open Shift Guard Seam (`apps/api/src/payments/payment.service.ts`):**
   - Supports manual recording of `CASH`, `CARD`, `CLICK`, `PAYME`, and `TRANSFER` payments in integer UZS (`BigInt`, `scale = 0`) with zero external gateway/webhook/autocharge integration (`OWNER-20261105-05`).
   - Preserves dual timestamps (`paid_at` external payment timestamp vs server `recorded_at` entry timestamp) on `payments` and `receipts` via additive migration `20261105000600_s10_payments_allocations_reversals_receipts`.
   - Enforces the S11 `CashShift` guard seam (`409 SHIFT_CLOSED` if the target shift is not `OPEN`; `403 POLICY_DECISION_NOT_CONFIRMED` on closed-shift backfill/reopen attempts) and updates `cash_receipts_uzs` / `expected_closing_cash_uzs` (for `CASH`) vs `non_cash_receipts_uzs` (for `CARD`/`CLICK`/`PAYME`/`TRANSFER`).
2. **`10.02` — Partial, Overpaid (`UnappliedCredit`), and Multi-Invoice Allocations (`apps/api/src/payments/allocation.service.ts`):**
   - Computes deterministic single- and multi-invoice allocations (`500,000 - 300,000 = 200,000` debt; `600,000` on `500,000` -> `500,000` allocation + `100,000` `UnappliedCredit`).
   - Enforces mandatory `promise_date >= centerTodayDate` (`422 PROMISE_DATE_REQUIRED_FOR_PARTIAL_PAYMENT`) whenever remaining invoice debt > 0 after payment, creating `PromiseToPay(status = 'ACTIVE')`, and automatically transitions active `PromiseToPay` rows to `FULFILLED` (emitting `PromiseFulfilled`) when subsequent payments clear invoice debt to `0`.
3. **`10.03` — Reason-Required Reversal Request & Director-Only Append-Only Execution (`apps/api/src/payments/reversal.service.ts`):**
   - Separates `ReversalOrRefundRequest` (`PENDING_DIRECTOR_APPROVAL` with `CRITICAL_RED` `RefundRecorded` outbox notification and zero balance change) from Director-only `ReversalOrRefundExecution` (`APPROVED_EXECUTED` / `REJECTED`).
   - Gates unconfirmed `D22` `CLOSE_WITH_CREDIT_NOTE` service-refund formulas with `403 POLICY_DECISION_NOT_CONFIRMED` while supporting `REOPEN_INVOICE_DEBT` accounting reversals (`CASE-13`, `CASE-14`).
4. **`10.04` — Internal Electronic Receipts (`apps/api/src/payments/receipts.service.ts`):**
   - Allocates center-scoped sequential receipt numbers (`RCP-YYYYMM-NNNNNN`) serialized via `pg_advisory_xact_lock`, sets `is_fiscal_tax_receipt = false` (`D13`), and returns reversal-aware receipt snapshots via `GET /api/v1/receipts/{receipt_id}`.
5. **`10.05` — Tests, CI Gate `G7`, and Docs:**
