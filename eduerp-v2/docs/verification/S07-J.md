## 2. Detailed Verification of `I03` & `I04`

### 2.1. `I03` — Revoked/Reassigned Substitute & Primary Teacher Idempotency Replay Prevention
- **Pre-Check Ordering:** Inside `GradesService.submitLessonGrades()`, `executeIdempotentOperation` invokes `authorizeBeforeReplayOrExecute: async (tx) => { await this.accessService.assertLessonAccess(tx, principal, lessonId, 'WRITE_GRADES'); }` inside the PostgreSQL transaction **before** querying `client_operation_logs`.
- **Two-Statement Post-Lock Snapshot:** `AcademicAccessService.assertLessonAccess()` first executes `SELECT ... FROM "lesson_occurrences" WHERE "center_id" = $1 AND "id" = $2 FOR UPDATE` and then queries `course_groups` and `substitute_assignments` in a second query so concurrent `revokeSingleLessonSubstitute`, `assignSingleLessonSubstitute`, or `updateOrArchiveCourseGroup` commits are guaranteed visible after acquiring the row lock.
- **No Premature Version Bump:** `authorizeBeforeReplayOrExecute` does not increment `lesson_occurrences.version`, so an authorized teacher replaying the exact same `Idempotency-Key` and request body (with the original `expected_version`) still receives `200 OK` from `client_operation_logs`.
- **Scenarios Proven in `ACAD-IT-12` & `ACAD-UNIT-05`:**
  1. Active Substitute A submits grade (`200`) -> replays same `Idempotency-Key` while still active (`200`, zero duplicate rows).
  2. Director revokes Substitute A (`200`) -> Substitute A replays exact same `Idempotency-Key` and body -> **`403 FORBIDDEN_OBJECT_SCOPE`**; fresh key -> **`403 FORBIDDEN_OBJECT_SCOPE`**.
  3. While Substitute A is active, original Primary Teacher is denied (`403`) on both fresh key and replay of their earlier cached `Idempotency-Key`.
  4. Reassignment `Substitute A -> Substitute B` -> Substitute A old/new key returns `403`, Substitute B succeeds (`200`).
  5. Parallel `POST /substitute/revoke` vs `POST /grades` replay -> serialized without 500 error, post-revoke replay returns `403`.
  6. Group primary teacher reassignment (`Primary 1 -> Primary 2`) -> `Primary 1` replay of old `Idempotency-Key` on open scheduled lesson returns `403`, while historical `COMPLETED` lesson teacher snapshot remains `Primary 1`.

### 2.2. `I04` — Authoritative Future Group-Specific & Course Tariff Resolution
- **Shared Resolver (`apps/api/src/academics/price-resolver.ts`):** Queries `course_price_history` for the target scope (`group_id = $3::uuid` for groups, `group_id IS NULL` for course defaults) ordered by `effective_from DESC, target_version_snapshot DESC, created_at DESC, id DESC`.
- **Timezone-Accurate Day Boundary:** Uses `formatUtcInstantInTimeZone(this.clock.now(), group.timezone)` to compute `todayInZone` (`YYYY-MM-DD`).
- **Scenarios Proven in `ACAD-IT-13` & `ACAD-UNIT-04`:**
  1. Before `effective_from` (`2026-11-09 23:30 Asia/Tashkent` = `2026-11-09T18:30:00Z`): `GET /api/v1/groups` returns `current_fee_uzs: "480000"`; `GET /api/v1/groups?as_of_date=2026-11-10` returns `current_fee_uzs: "480000"` and `effective_fee_as_of_uzs: "680000"`.
  2. Across midnight in `Asia/Tashkent` (`2026-11-10 00:30 Asia/Tashkent` = `2026-11-09T19:30:00Z`) and on `2026-11-11`: `GET /api/v1/groups` and `PATCH /api/v1/groups/:group_id` return `current_fee_uzs: "680000"` (selecting the latest same-date revision `target_version_snapshot = 3` over `2`).
  3. On/after second future change (`2026-11-20`): `GET /api/v1/groups` returns `current_fee_uzs: "9007199254740999"` (`BigInt > Number.MAX_SAFE_INTEGER`).
  4. Sibling Group 2 under the same course and Course `default_monthly_fee_uzs` remain `"480000"`.
  5. Teacher `GET /api/v1/groups` omits `current_fee_uzs`, `effective_fee_as_of_uzs`, `effective_from_date`, and `as_of_date`.
  6. Historical `invoices.tariff_snapshot_uzs` remains `"480000"`.
