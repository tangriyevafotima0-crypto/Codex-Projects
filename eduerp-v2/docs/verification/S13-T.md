## 1. Root-Cause Analysis & Remediations (`T01`–`T06`)

### `T01` — Gate G10 Fixture `23505` Collisions & Real `WORKER-IT-13` Coverage
- **Root Cause (`S13-S` §2.1 & §3.6):**
  1. `WORKER-IT-03`, `WORKER-IT-12`, and `WORKER-IT-16` called `createInvoiceAndPromiseFixture`, which repeatedly inserted `'ACTIVE'` enrollments using the same `(CENTER_A.studentId, CENTER_A.groupId)` pair, violating partial unique index `idx_enrollments_active_student_group` (`23505`).
  2. `WORKER-IT-12` updated `invoices.remaining_debt_uzs = 150000` without updating `allocated_paid_uzs = 350000`, which would violate `chk_invoices_remaining_debt_formula` (`remaining_debt_uzs = effective_net_charge_uzs - allocated_paid_uzs`).
  3. `WORKER-IT-06` inserted `lessonId` and `cancelledLessonId` with identical `(group_id, '2026-11-05T09:00:00Z')`, violating `uq_lesson_occurrences_group_starts` (`23505`).
  4. `WORKER-IT-13` did not execute the leap-year `2028-02-29` `CALENDAR_MONTH` window, `PREVIOUS_AND_CURRENT_CYCLE` catch-up, or `PKG:1 -> PKG:2` package renewal in the test body.
- **Fix Implemented:**
  - Updated `createInvoiceAndPromiseFixture` in `apps/worker/test/worker-integration.test.ts` to create a fresh isolated `students` row and active `guardian_students` link per fixture (unless an explicit `studentId` is provided) and insert a matching `payment_allocations` row.
  - Updated `WORKER-IT-12` to insert the second partial `payments` + `payment_allocations` row and update both `allocated_paid_uzs = 350000` and `remaining_debt_uzs = 150000`.
  - Updated `WORKER-IT-06` to use distinct `starts_at_utc` timestamps (`08:50:00Z`, `08:55:00Z`, `09:00:00Z`) for `SCHEDULED`, `CANCELLED_BY_CENTER`, and `COMPLETED` lessons within the 20m scan window.
  - Expanded `WORKER-IT-13` to execute and assert `CALENDAR_MONTH` Feb 2026 (`2026-02-28`) vs leap Feb 2028 (`2028-02-29`) + `PREVIOUS_AND_CURRENT_CYCLE` catch-up at `2028-03-05`, `ROLLING_MONTH` `Jan 31 -> Feb 28 -> Mar 28`, and `LESSON_PACKAGE_12` `PKG:1 -> PKG:2` (24 rows in `billing_cycle_lesson_allocations`).

### `T02` — Bounded Catch-Up Eligibility Horizon & Single Canonical Billing Engine
- **Root Cause (`S13-S` §3.1):**
  1. In `SchedulesWorker.runBillingCycleCutoffAndCatchUpJob`, `ROLLING_MONTH` checked `nextStart <= cutoffHorizonDate`, which caused an enrollment with an old `enrolled_at_date` (`2026-01-31`) to issue one historical past cycle per poll under `CURRENT_CYCLE_ONLY` (`3` polls -> `3` historical cycles -> `1,800,000 UZS` debt).
  2. `CanonicalSqlBillingCycleWorkerPort` duplicated ~600 lines of Stage 08 billing calculation and SQL instead of calling the single canonical Stage 08 engine.
- **Fix Implemented:**
  - Extracted the single canonical billing calculation and transactional SQL issuance engine into `packages/contracts/src/billing-engine.ts` (`executeCanonicalBillingCycleIssuanceInTx`, `loadCanonicalInvoiceResponseInTx`) and wired both `apps/api/src/billing/invoice-generator.ts` and `apps/worker/src/schedules.worker.ts` (`CanonicalSqlBillingCycleWorkerPort`) directly to it.
  - Enforced durable DB-backed bounded catch-up eligibility in `SchedulesWorker.runBillingCycleCutoffAndCatchUpJob`:
    - `CURRENT_CYCLE_ONLY`: Only issues a cycle whose service period covers `referenceDate` (`candidateStart <= referenceDate && referenceDate <= candidateEnd`). Unissued historical cycles (`candidateEnd < referenceDate`) and unconfirmed old first-cycle enrollments (`!hasPriorCycle && enrolledAtStr < earliestPermissibleCalStart`) are never issued or drained across polls or restarts (`0` extra cycles/debt), recording a deduplicated `BILLING_HISTORICAL_RECONCILIATION_DEFERRED` audit log.
    - `PREVIOUS_AND_CURRENT_CYCLE`: Issues at most the `[previous, current]` 2-cycle window covering `referenceDate`.
  - Added `WORKER-IT-17`, `WORKER-IT-18`, and `WORKER-IT-19`.

### `T03` — Feature-Specific Per-Center Notification Policy (`UNCONFIGURED` Default)
- **Root Cause (`S13-S` §3.2):**
  `RemindersWorker.resolveEffectiveChannelPolicy` fell back to `billing_policy_versions.policy_confirmation_status = 'CONFIRMED'` as `CONFIRMED_ADMIN_AND_GUARDIAN` and read undocumented `process.env.PROMISE_REMINDER_CHANNEL_POLICY`, violating `OPEN_CHANNEL_02` and `OWNER-20261105-04`.
- **Fix Implemented:**
  - Added additive migration `20261106000900_s13_notification_policy_and_delivery_scope/migration.sql` adding `notification_policy_status` (`DEFAULT 'UNCONFIGURED'`), `promise_reminder_channel_policy` (`DEFAULT 'UNCONFIGURED_CHANNEL_POLICY'`), and `notification_policy_effective_until` on `billing_policy_versions`, plus `target_student_id`, `payload_projection_json`, and `policy_version_id` on `notification_deliveries`.
  - Removed the `process.env.PROMISE_REMINDER_CHANNEL_POLICY` fallback and the `policy_confirmation_status = 'CONFIRMED'` -> `CONFIRMED_ADMIN_AND_GUARDIAN` fallback from `RemindersWorker`.
  - Made `resolveEffectiveChannelPolicy` and `resolveEffectiveChannelPolicyMetadata` `public`, requiring `notification_policy_status = 'CONFIRMED'`, confirmed channel policy, and valid effective date window, while recording `policy_version_id` provenance on `PromiseDue` and `notification_deliveries`.
  - Added send-time policy re-verification in `OutboxWorker.processNotificationDeliveriesForEvent` so revoked, expired, or narrowed policies (`CONFIRMED_ADMIN_AND_GUARDIAN` -> `CONFIRMED_GUARDIAN_ONLY`) suppress stale queued deliveries before external send.
  - Added `WORKER-IT-20`.

### `T04` — Exact Guardian–Student Scope & Recipient-Specific Payload Projection
- **Root Cause (`S13-S` §3.3):**
  For batch `AttendanceSubmitted` / `AttendanceCorrected` events, `event.payload_json.student_id` was `undefined`, so `($3::uuid IS NULL OR gs."student_id" = $3::uuid)` evaluated to `TRUE` if the guardian had *any* active child in the center, and passed the full unprojected `event.payload_json` containing other children's student IDs to `transportAdapter.sendNotification`.
- **Fix Implemented:**
  - Implemented `extractEventTargetStudentIds` and `buildGuardianScopedPayloadProjection` in `apps/worker/src/outbox.worker.ts`.
  - During staging (`ensureNotificationDeliveriesStagedFenced`) and right before external send (`processNotificationDeliveriesForEvent`), `OutboxWorker` queries live `guardian_students` joined with `students`, `guardians`, and `guardian_telegram_links` for the exact target student IDs of the event (`gs.student_id = ANY($3::uuid[])`).
  - If zero target students from the event remain actively linked to the guardian at send time (even if another sibling remains active!), the delivery is marked `SKIPPED_UNLINKED` (`0` sends).
  - Outgoing `request.payload` is projected to include only the guardian's currently permitted child(ren), persisted in `notification_deliveries.target_student_id` and `payload_projection_json`.
  - Added `WORKER-IT-21`.

### `T05` — Bounded Shutdown on Slow/Hung DB Queries, Subprocess SIGKILL Recovery & Worker Dependency Isolation
- **Root Cause (`S13-S` §3.4 & §3.5):**
  `WorkerRuntimeSkeleton.stop()` raced `inFlightTick` against `shutdownTimeoutMs` but then awaited `this.db.close()` -> `pool.end()` unboundedly, hanging when a slow/hung PG query held a checked-out client, and emitted `worker_stopped_gracefully` even on timeout. `apps/worker/package.json` also relied on root hoisted `pg`.
- **Fix Implemented:**
  - Updated `WorkerDatabase` (`apps/worker/src/database.ts`) to track active checked-out `PoolClient` instances and implement bounded `close(timeoutMs, forceAbortActive)` that destroys/releases hung active clients and bounds `pool.end()`.
  - Updated `WorkerRuntimeSkeleton.stop(signal)` (`apps/worker/src/main.ts`) to share a single `stopPromise` across concurrent callers, bound total shutdown time, emit `worker_stopped_gracefully` only on clean drain vs `worker_shutdown_bounded_timeout` on timed-out drain, and exit non-zero in `bootstrapWorker` when drain timed out.
  - Explicitly declared `"pg": "8.23.1"` and `"@types/pg": "8.23.1"` in `apps/worker/package.json` (`needs_manager_dependency_refresh: true` in `SUBMISSION.json`).
  - Added `WORKER-IT-22`, `WORKER-IT-23`, and `WORKER-IT-24`.
